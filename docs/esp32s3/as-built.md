TD62083接続時の電源投入・USB書込み・リセット成功とファンの不意動作を実機で確認する。

## 最初の動作確認

既定は `TEMPESCOPE_BENCH_MODE=1`。Wi-Fi・Matterを起動せず、未接続の水位/停止入力を
安全として偽装せず、USBシリアルから単発の監視付き試運転だけを行う。
115200bps・改行付きで以下を送る。各コマンドは他の負荷を同時駆動せず、終了後は全出力OFF。

|コマンド|動作|
|---|---|
|red / green / blue / white|PWM 64/255、最大5秒|
|fan|最大5秒|
|mist|最大2秒。初期状態は拒否|
|pump|最大1秒。初期状態は拒否|
|off|全出力OFF|
|status|モード・ドライバ初期化・負荷許可・動作中の状態|

動作中の追加指令は拒否し、時間を延長しない。pump/mist間で共通の60秒開始間隔を設け、
offしても間隔は解除しない。USB切断後も時間上限で停止する。loop停止時は2秒WDTでリセットを要求する。
起動・リセット後は必ずOFF。WDTの実停止時間やリセット中の外部回路電位は実機未検証。

`LocalConfig.example.h` を `LocalConfig.h` にコピーして設定する。
LED・ファンの試験には `TEMPESCOPE_HARDWARE_VALIDATED` の変更は不要。
ミストは5V電源/リレー駆動と水深を確認後、`TEMPESCOPE_BENCH_MIST_ENABLED=1` で許可。
ポンプは以下の電気的課題を解消し、水を入れて監視できる場合のみ
`TEMPESCOPE_BENCH_PUMP_ENABLED=1` で許可。ベンチモードに空運転検知はない。
この許可は自動運転の水位保護の代わりにはならない。

## コードで解決できない事項

- 図のR4は150kΩ、Q1は2N3904。VBEを仮に0.7Vとすると、R4電流は約17µA。
  10kΩプルダウンにも約70µA必要なため、そのままでは通常のベース電圧に達しない。
  実物が150Ωなどであれば図の値を修正すること。ただし抵抗だけ変えればよいとは限らず、
  ポンプの始動/拘束電流、GPIO電流、トランジスタ飽和・損失の確認が必要。
  2N3904のコレクタ電流絶対最大は200mAで、ポンプの適合は未確認。
- R1/R2/R3も図では150kΩ/75kΩ/75kΩ。LED定格と実装抵抗値を確認。
  値が図どおりならソフトのPWMを増やしても必要な電流にはならない。
- TD62083を3.3Vで直接駆動した際のリレー・ファン電流/出力電圧、
  7805発熱とWi-Fi時の電圧降下は実測が必要。COMは5V、クランプダイオード利用。
- HPHの2–8/4–7接続がシンボル内で描かれたことは確認したが、実配線の導通は未確認。

2N3904参照: https://www.onsemi.com/pdf/datasheet/2n3904-d.pdf

## 自動天気・Alexaへ進むとき

水位2入力、NC停止接点、必要なら解除ボタンを予約端子に追加する。
`TEMPESCOPE_BENCH_MODE=0` とし、commissioning.md の電気・安全試験後に
`TEMPESCOPE_HARDWARE_VALIDATED=1` にする。自動モードでは従来の水位/停止保護、
Wi-Fi断・天気期限切れでOFF、復旧後再ON要求を維持する。
現在の水位/停止なしの構成で自動モードを有効にしても、未接続入力によって負荷は停止する。
